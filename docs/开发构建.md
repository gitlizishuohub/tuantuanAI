# 开发、测试与打包

适用：Windows x64，项目根目录执行 PowerShell 命令。当前采用 Electron + React/TypeScript + Vite、FastAPI 本地工作进程和 SQLite。普通最终用户只需安装完成的桌面程序；以下环境仅开发者需要。

## 环境准备

开发机使用 Node.js/npm 和 Python。Vite 7 要求兼容的 Node 版本（至少 Node 20.19 或 22.12）；建议使用 Node 22 LTS 兼容环境。Python 当前开发环境为 3.13，其他版本需自行验证。精确实际环境及测试结果以验收记录为准。

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements-dev.txt
npm install
npm run dev
```

存在 `package-lock.json` 时，复现构建改用 `npm ci`。`backend/requirements.txt` 固定直接运行依赖；`backend/requirements.lock.txt` 为当前开发环境 `pip freeze` 记录，含开发工具及间接依赖，可用于更严格的 Python 环境复现。

`npm run dev` 同时启动 Vite 和 Electron；仅打开 Vite 页面不能使用桌面桥接功能。关闭 Electron 会停止开发服务。开发启动本地 Python 时固定使用根目录 `.venv/Scripts/python.exe`。

当前 `package-lock.json` 解析版本：Electron 45.0.0、React 19.3.1、Vite 7.3.7、TypeScript 5.9.3、electron-builder 26.15.3、Playwright 1.64.1。`package.json` 使用版本范围，复现时以锁文件和 `npm ci` 为准。

## 检查与构建

```powershell
npm test
npm run build
npm run test:desktop
npm run pack
npm run dist
```

各命令作用：

| 命令 | 输出或用途 |
| --- | --- |
| `npm test` | 后端 pytest 回归；不能证明真实模型质量 |
| `npm run build` | TypeScript 检查及 `dist/` 前端构建 |
| `npm start` | 通过 `scripts/start.cjs` 清理宿主 `ELECTRON_RUN_AS_NODE` 后启动已构建的桌面程序 |
| `npm run test:desktop` | 桌面冒烟脚本；实际覆盖范围看脚本与验收记录 |
| `npm run build:worker` | PyInstaller 生成 `build/worker/defense-worker/`，包含 Python 运行时 |
| `npm run pack` | 构建前端与工作进程，输出 `release/` 下未安装目录版本 |
| `npm run dist` | 构建 Windows NSIS 安装程序，输出 `release/` |

验证独立工作进程可运行 `node scripts/smoke-worker.cjs`。验证打包exe的完整桌面流程时，在PowerShell设置测试目标再运行冒烟：

```powershell
$env:DEFENSE_SMOKE_EXECUTABLE = (Resolve-Path 'release/win-unpacked/答辩风洞.exe').Path
npm run test:desktop
Remove-Item Env:DEFENSE_SMOKE_EXECUTABLE
```

冒烟使用独立测试数据，01–07截图写入 `docs/screenshots/`。实际通过范围以验收记录为准。

打包包含 Electron、界面、Python 工作进程与内置示例。NSIS 支持选择安装路径和创建桌面快捷方式，卸载默认保留用户数据。下载 Electron、NSIS 等构建资源需要网络；资源下载失败不能算打包通过。版本、产物大小与校验值应在生成后记录，不预填。

## 目录与运行机制

| 路径 | 职责 |
| --- | --- |
| `src/` | React 界面、桌面桥类型和样式 |
| `desktop/` | Electron 主进程、白名单 IPC、文件对话框、凭据保存 |
| `backend/app.py` | 本地 API、材料、画像版本、会话、报告与备份 |
| `backend/engine.py` | OpenAI 兼容调用、引用校验、离线规则 |
| `backend/examples.py` | 两个自编虚构教学案例 |
| `backend/worker.py` | 后台工作进程入口 |
| `backend/tests/` | 后端回归（由测试任务补齐，以实际文件为准） |
| `scripts/` | 开发启动和桌面验证 |
| `docs/` | 交付文档、评测集和验收证据 |

主进程每次启动产生随机凭据，经标准输入交给只监听回环地址的工作进程；前端经受限 IPC 访问服务，不持有本地服务凭据。模型密钥在主进程使用系统能力加密，运行中发给工作进程，备份与报告不包含密钥。

开发或自动化时，可在启动前设置 `DEFENSE_DATA_DIR` 指向独立测试目录，避免混入个人材料；打包版忽略此覆盖。`DEFENSE_DEV_URL` 仅允许固定的本机 Vite 地址。`DEFENSE_TEST` 供自动化跳过退出确认，普通运行不要设置。模型调用用量元数据持久化到SQLite，保留最近200条，不记录密钥或请求正文。

## 发版复核

先跑回归和桌面冒烟，再生成安装包。在无 Python/Node.js 的干净 Windows 10/11 x64 虚拟机中验证安装、中文及空格路径、双击启动、关闭无残留进程、离线历史查看、备份恢复、重装与卸载。检查 100%/150%/200% 缩放和最小窗口。

真实模型验收需用户自行在设置填写有效配置，执行固定集并保存脱敏结果。严禁把 API Key 写入仓库、截图、日志、备份或安装包。发布前整理依赖许可和签名状态；目前不承诺已有签名或完整许可证审计。

## 本次环境故障排查

本次开发机的虚拟环境没有可用 pip，`ensurepip` 亦不可用；经主任务验证，使用系统 pip 指定目标虚拟环境可安装依赖和生成快照：

```powershell
python -m pip --python .venv install -r backend/requirements-dev.txt
python -m pip --python .venv freeze
```

本机 npm 安全策略没有自动执行 Electron 安装脚本；在已确认依赖来源后，主任务尝试单独执行 `node node_modules/electron/install.js`，下载仍停滞，随后改用官方运行时下载与SHA256校验，最终结果见验收记录。遇到“Electron failed to install correctly”时可检查运行时是否已下载。此说明记录本次环境，不代表所有机器都需要手动操作。
